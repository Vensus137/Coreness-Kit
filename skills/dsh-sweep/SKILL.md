# Sweep

A pass over a project's scaffolding — the law, the procedures, the documents as a class — run by several members at once and ended by diffs that land. It exists because scaffolding grows by accretion: a rule answers a moment, the moment passes, the rule stays, and nobody re-reads the whole of it. A sweep re-reads the whole of it, and its result is not a report: it is a set of prepared changes plus the decisions the user alone may take.

**The shape below is a floor, not a script.** Where a subject needs a phase this file does not name, take it and say why. Both runs of this procedure so far found their sharpest findings *outside* the plan: a citation that resolved green over a sentence that had gone false, and a repair that exposed the very defect it repaired. A sweep that follows the letter and skips what it sees has failed the larger half of its job.

**It is expensive, and it says so.** The first run behind this file used fourteen members and seven areas. Neither is a figure to copy. Use it on the scaffolding — never on a task. A task has a spec; a sweep has a subject.

## 1. Zones first, before any work

The first thing the sweep asks the user, in one batch with defaults:

- **what may be touched** — which paths are ours, which are another hand's, which are never touched;
- **what the lead may land alone** when the checks are green, and **what waits for the user's word** — a rule of the law, a published snapshot, anything contentious;
- **how far the sweep goes** — one subject, or the whole scaffolding.

Without this the sweep either stands still or oversteps. The runs behind this file did both: a scope that kept the law out of the first pass, and a plan stopped before its first strip.

## 2. The shape

1. **Areas.** The scaffolding is divided into subjects, one reader each, one file each. A reader reads its subject whole — not from summaries, and not from the previous pass's prose. Experimental rules are read with special attention; if there are none, nothing is owed.
2. **Proposals.** The same reader proposes for its own subject: it holds the material. A proposal that only describes is not a proposal.
3. **One challenge round, and a second only if an objection moved a proposal's ground.** Three critics who read from different angles: the law (does the proposal hold against the rules in force), what it breaks (the corpus, the citations, the neighbours), the evidence (does the evidence carry the claim). Each objection carries an address and the condition under which it survives.
4. **Answers.** One file per area, by its author: what was accepted and what changed, what was refused and the address that settles it. Numbers the critics checked and found **right** are recorded as confirmations — a critic that only subtracts is half a critic.
5. **Patches.** Prepared diffs, one file, one writer. `git apply --check` reads and writes nothing; it is the floor of the check, never its ceiling: the applied result is replayed against the intent before it lands.
6. **One landing, one hand.** A second writer in one tree is a race — settled in §1's zones, by write zones or by a copy per hand — and the lead lands where the tree is quiet.
7. **Verification after the landing.** The project's cheap check is run on the result; a check that boots the live environment is hand-run, and what was not run is named.

## 3. The members, and what each owes

- **One reader per area.** It reads its subject, writes its area file, then its proposal. It does not write another area's file, ever.
- **Three critics, never authors** of what they judge. Majority decides what survives; **a refusal escalates to the user and is not the truth.** The sweep reduces uncertainty; it does not own it.
- **The lead writes no area of its own**; when an owner is gone it repairs what that owner can no longer correct and names the repair (§5).
- **A card is a document like any other**, checked against the specification it summarises; the executor sees the gap.

## 4. What an artifact carries

- **A finding**: `claim / kind / trace / cost / proposal`. Every trace opens the source at the moment it becomes load-bearing. **A retelling is not a reading**, and a summary is a prompt to open the file, never a substitute for it.
- **A proposal**: what changes, in which file, **what it removes**, its price, what breaks if it is wrong, what it does not do, and which alternatives lost and why. A proposal whose "what it removes" is empty is a rule that only adds — refuse it.

## 5. The rules that cost the most

Each of these is written from a failure, not from a preference.

- **Fix the zones in advance, and keep one owner per file for its whole life.** A write scope fixed per phase leaves an artifact nobody may correct; the lead ends up repairing files it did not write.
- **A partial duplicate is removed partially.** Twice in one run, deleting a "restatement" carried a rule out with it. Slimming removes what is written twice, not what is written once.
- **Collisions are resolved by the authors yielding, not by the verdict.** Name the line, name the writers, let them settle it; the verdict records the settlement.
- **The lead shows its own errors.** A ledger with a corrections section — wrong numbers, invented times, a state line dated a day ahead, a card that forgot an act, a command that could not run — is not self-flagellation; it is the evidence that the sweep's own numbers were checked. A pass that audits others' retellings and hides its own has no standing.
- **Name what the check does not show, in the same report** — an address pass can print a resolved citation over a false sentence.
- **The patch phase is not mechanical**: the findings that matter most arrive with the diffs.
- **Commit by explicit paths, and expect another hand.** A second writer rewrote a line a prepared patch sat on and swept two finished patches into its own commit. Prepare diffs in the pass's own folder; never `git add -A`.
- **A list of acts is a document nobody checks.** The plan's own order of acts forgot a decided act, and only the executor saw it.

## 6. What it refuses

- **Truth.** The sweep proposes, challenges and escalates; the user decides what is contentious. A majority of critics is not a proof.
- **A promise of cheapness**, and a fixed roster: the areas are counted from the subject, not from a template.
- **A second picture, a second backlog, a parallel index** that must be kept true by hand.
- **One face of one thing** — a plugin, a module, a document — is `reflection`'s, and it changes nothing; a sweep takes the scaffolding as a class and ends in diffs.
- **Working without an owner**: a file whose keeper is unnamed will rot, and the rot will be found by the next sweep.

## 7. The end

The sweep ends with what the areas produced: **prepared diffs** in the pass's own folder where they were asked for, **the user's decisions** listed apart from the decided ones, and **the record** — the ledger, with its corrections section, handed back with the result. The landing is a separate act, inside the zones the first question fixed. What was not settled is named as not settled; a finding that could not be pinned is more useful as an open question than as a confident sentence.
