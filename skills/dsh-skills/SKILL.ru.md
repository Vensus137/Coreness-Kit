# Процедуры в DeepSeek Harness

> RU-зеркало для чтения; канон — SKILL.md рядом. Пометки `>` отмечают, что против прежней редакции (клон кита) добавилось при просмотре 13.10: раздел «Где живёт правило».

Процедура доходит до агентов одной из двух дверей: файл в сканируемом корне или регистрация плагином. Первая — дверь этого кита; вторая принадлежит собственной поставке платформы и названа здесь лишь затем, чтобы её не спутали с первой.

## Файловые навыки

Провайдер `@deepseek-ai/dsh-skill-filesystem` сканирует четыре корня в порядке ранга, и ещё два существуют, когда строка их настраивает:

| Ранг | Корень | Источник |
| --- | --- | --- |
| 100 | `<project>/.dsh/skills` | `project-dsh` |
| 200 | `<project>/.agents/skills` | `project-agents` |
| 300 | папки, которые называет строка | `customSkillDirs` |
| 400 | `<dsh home>/skills` | `user-dsh` |
| 500 | `~/.agents/skills` | `user-agents` |
| 600 | папка, поставляемая внутри пакета | `bundledSkillDir` |

Процедура — это папка `<name>/SKILL.md` или плоский файл `<name>.md` в вершине корня; вложенные `**/SKILL.md` намеренно не обнаруживаются. Корень проекта — ближайший предок, держащий `.git`; пользовательский корень DSH пропускает своё дитя `.system`. Провайдер следит за корнями, поэтому новая, переименованная или удалённая процедура доходит до следующего каталога без перезапуска.

**Дверь должна быть открыта.** Веб-поверхность пакета выключает хост-строку этого провайдера — «presets own local discovery» — и тогда сессия видит только то, что регистрирует слой. Строка включается назад из патча профиля:

```yaml
- id: skill-filesystem
  disabled: false
```

После одного перезапуска корни работают для каждого проекта профиля. С включённой строкой процедура грузится по имени из `<dsh home>/skills`. Каталог — собственная публикация платформы: он не появляется, пока предполётный шаг возвращает решение неизменённым и ничего не записано в лог, поэтому «пришёл ли он сегодня» измеряется, а не предполагается.

## Процедуры внутри пакета

Платформа несёт собственные процедуры внутри пакетов: строка направляет `customSkillDirs` провайдера на папку пакета, и пакет может также зарегистрировать процедуру кодом при загрузке своего слоя. Обе двери существуют, обе — собственные у платформы, и продукту они могут понадобиться для своей поставки. Этот кит не пользуется ни одной: его процедуры — файлы в корне, который среда сканирует, а тело в коде — процедура, чей текст никто не правит как текст. Папка в корне репозитория — не дверь вовсе.

## Какую дверь выбрать

- Нужна в каждом проекте машины, репозиторий ни при чём — файл в `<dsh home>/skills`.
- Нужна одному репозиторию — файл в `<project>/.dsh/skills`, или в `.agents/skills`, когда процедура делится с другими агентами.

## Где живёт правило

Процедура — не дом для правила. Компакция вынимает из вида модели отрезок видимой поверхности; после неё сами себя выводят заново цепочка инструкций, снимок рантайм-контекста и каталог навыков — тело навыка не возвращается, а тело сверх лимита прунера режется в транзакции, пишущей чекпойнт. Значит, домов три: правило, которому надо быть **в силе**, живёт в **секции промпта**; правило, которому надо быть **перечитываемым**, — в **файле инструкций** на цепочке сессии (AGENTS.md проекта); а **навык несёт процедуру, а не правило** — то, что его читатель должен **сделать**, удержанное под лимитом. Лимит и рез — собственные числа платформы, читаемые там, где стоят.

> Добавлено при просмотре: «Где живёт правило» — дома правила против компакции; в прежнем законе 1.35 это жило в разделе «In DeepSeek Harness», у которого в законе 2.0 дома нет.

## Проверка

Назови процедуру по имени: она названа, она грузится, и её базовый каталог указывает на корень, из которого пришла. Каталог сессии — публикация платформы, а не этого провайдера, поэтому имя — дверь, которая есть всегда.

## Чего не делать

- Не полагать, что файл дошёл, не спросив каталог: файл в корне, который не сканируется, — молчаливая подмена.
- Не держать одну процедуру в двух дверях сразу: текст получает одного владельца.
